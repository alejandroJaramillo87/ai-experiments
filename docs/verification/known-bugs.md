# Known bugs by runbook step

**Operational. A live ledger read alongside the runbook steps and updated as defects are fixed: move a row to Resolved rather than deleting it, so the KB ids stay stable. Keep the locations current — both documentation gates exempt this directory by path.**

Every defect the WI-14 capstone review and its Opus re-verification confirmed, indexed so the operator running the [hardware verification runbook](README.md) knows which known bugs to expect at each step. The code passed its sandbox unit tests; these were latent defects in paths those tests never exercised. Of the 66 ledgered, 36 pure-Python defects were fixed with regression tests in the sandbox pre-fix pass and a further 11 during the hardware campaign (see the Resolved sections below); the 19 still open are GPU-runtime, pinned-library, or design-decision defects the sandbox cannot observe. Fix those against the real traceback as each step reaches them.

KB-57 through KB-66 were found later, by the hardware campaign itself rather than by the WI-14 panel, so they carry no panel confidence count. KB-57, KB-58, KB-60, and KB-62 were confirmed directly against the pinned SAELens 6.46.0 source; KB-57 was also reproduced in the sandbox, and KB-59 was observed three times on the workstation before it was understood as one defect. KB-62 through KB-66 all surfaced from the same first successful `make sae-train` on 2026-08-08: KB-63 killed the run at teardown, the next three were only observable once it got far enough to finish, and KB-66 only once the first `make sae-eval` was run against the result.

## How to read this

- **KB-nn** is a stable identifier; the runbook steps reference these IDs. IDs are ordered by the first campaign step where the bug appears.
- **Step(s)** are the runbook entries (README phase files) where the bug manifests; a bug listed at more than one step recurs at each.
- Each was confirmed by an independent three-reviewer adversarial panel (reviewers instructed to refute by default; a bug is listed only when at least two of three upheld it). Confidence is the upheld count.
- These are open unless a later commit resolves them; when one is fixed, move its row to Resolved rather than deleting it, so the IDs stay stable.
