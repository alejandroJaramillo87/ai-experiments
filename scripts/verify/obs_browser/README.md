# Run dashboard browser verification

Opt-in harness that verifies the run dashboard (roadmap OBS-11 and OBS-12) in
a real Chromium instance. It covers the checks a Python unit test cannot make:
uPlot chart creation, marker ingestion, log filter interaction, the hostile
`<!--<script` payload rendering as text instead of blanking the page, and the
live page extending its charts and log tail from a running `report --serve`
process.

The harness is not part of the pytest suite or the `make quality` gate. Run it
manually after changes to `common/obs/viewer.js`, `common/obs/dashboard.py`,
or `common/obs/serve.py`.

## Requirements

- Node.js 18 or later with `npm` on the path.
- `uv` on the path (the harness builds the snapshot with
  `uv run --no-sync python -m training report`).
- A Chromium or Chrome binary. The harness looks under
  `/opt/pw-browsers/chromium-*/chrome-linux/chrome` (the Claude Code cloud
  sandbox layout) and falls back to the `PW_CHROMIUM` environment variable.

## Usage

```bash
cd scripts/verify/obs_browser
npm install
node check.mjs
```

On a workstation with a system Chromium:

```bash
PW_CHROMIUM=$(command -v chromium) node check.mjs
```

`npm install` fetches only `playwright-core` (pinned exact version, no browser
download). `node_modules/` is gitignored.

## What it checks

Snapshot page (generated by the real `report` subcommand, loaded over
`file://`):

- Three uPlot charts render for the loss, learning rate, and throughput
  groups; the empty device-memory group creates no chart.
- The `checkpoint_saved` and `watchdog/*` records become markers.
- All fixture log rows render; the search filter narrows to the matching row;
  the level filter keeps warning rows and unknown-level rows.
- A log message containing `<!--<script` renders as text and the page reports
  zero script errors.

Live page (served by a spawned `report --serve --port 0` process):

- The header arrives via polling.
- Lines appended to `metrics.jsonl` extend the chart data.
- Lines appended to the event file appear in the log tail.

All waits use `waitForFunction`; the harness contains no sleeps. Exit code 0
and the final `ALL CHECKS PASSED` line signal success.
